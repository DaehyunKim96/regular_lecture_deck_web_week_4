# DESIGN.md

이 문서는 "회의는 끝났는데, 일은 왜 다시 시작될까" 발표자료의 시각 디자인과 문장 톤을 고정하는 디자인 계약이다. `design-preview.html`에서 확정한 색상·서체·여백·레이아웃·컴포넌트를 기준으로 삼는다. 발표 내용의 유일한 출처는 `presentation_sample/content/outline.md`이며, 이 문서는 그 내용을 어떻게 보여줄지만 정의한다.

## 1. Visual Theme & Atmosphere

- 장면: 회의실 화이트보드에 마커로 쓴 결정 카드. 장난스럽지 않은 실무적 인상을 준다.
- 분위기 키워드: 절제된 · 실무적인 · 신뢰가는.
- 정보 위계 원칙: 모든 슬라이드에서 "결정"과 "다음 행동"이 가장 먼저 읽히고, "이유·확인할 점" 같은 보조 정보는 항상 그 다음에 읽히도록 크기·색상·배치를 배정한다.
- 여백은 넉넉하게 두고, 좌우 대칭 구성 대신 비대칭 구성을 기본으로 한다.
- AI·미래·혁신을 연상시키는 추상적 장식(광선, 네트워크 노드, 로봇 아이콘 등)은 쓰지 않는다. 시각적 관심은 항상 수치·비교·흐름·다음 행동 같은 원고의 실제 정보로 향한다.

## 2. Color

| 역할 | HEX | 사용 규칙 |
| --- | --- | --- |
| Canvas (배경) | `#F6F4EF` | 모든 슬라이드의 기본 배경. 그라데이션이나 패턴 없이 단색으로만 사용한다. |
| Surface (표면) | `#FFFFFF` | 결정 카드처럼 배경과 구분되는 표면이 필요할 때만 사용한다. 그림자 없이 1px 테두리(Line 색)로만 경계를 만든다. |
| Text (본문) | `#22262B` | 제목·본문의 기본 글자색. |
| Muted (보조) | `#6B6F76` | 캡션, 라벨, 이유·확인할 점처럼 보조 정보의 글자색. 본문보다 항상 낮은 시각적 우선순위를 가진다. |
| Line (구분선) | `#D8D4C9` | 구분선, 그리드 보조선, 카드·표의 테두리. 배경과 표면을 구분하는 유일한 수단이며 그림자를 대체한다. |
| Accent (강조) | `#C1440E` | 슬라이드당 정확히 1개 요소에만 사용한다(예: 핵심 지표 하나, 결정 카드의 "결정" 값, 흐름의 마지막 단계). 배경·본문·보조 텍스트에는 쓰지 않는다. |

- 색상은 이 6개 외에 임의로 추가하지 않는다. 새로운 색이 필요하면 이 표를 먼저 개정한다.
- 강조색을 슬라이드에 두 곳 이상 쓰면 위계가 무너진 것으로 보고 하나로 줄인다.

## 3. Typography

- 제목 서체: **Pretendard** (Bold, 700). 본문 서체: **Pretendard** (Regular, 400). 캡션·라벨·데이터 서체: **IBM Plex Mono** (Regular/Medium).
- 두 서체 계열(제목·본문용 Pretendard vs 라벨·수치용 IBM Plex Mono)의 대비로 "말"과 "기록된 사실"을 시각적으로 구분한다.

| 용도 | 서체 | 크기 (1920×1080 기준) | 굵기 |
| --- | --- | --- | --- |
| H1 (표지 제목) | Pretendard | 64px | Bold |
| H2 (슬라이드 제목) | Pretendard | 44px | Bold |
| Body (본문) | Pretendard | 22px | Regular |
| Caption / Label (라벨, 발표자 노트 태그) | IBM Plex Mono | 16px | Regular |
| Metric-Primary (슬라이드의 핵심 지표 1개) | Pretendard | 96px | Bold, Accent 색 |
| Metric-Secondary (같은 슬라이드의 보조 지표) | Pretendard | 54px | Bold, Text 색 |

- 한 슬라이드에 지표가 여럿이면 가장 중요한 하나만 Metric-Primary(Accent)로, 나머지는 Metric-Secondary(Text 색)로 낮춘다.
- 작은 화면 대응을 위해 실제 구현 시 각 크기는 `clamp(최소값, 1920px 기준 vw, 최대값)`으로 비례 축소하되, 최대값은 위 표의 px를 넘지 않는다.

## 4. Spacing & Grid

- 캔버스 기준: 1920×1080px.
- 외곽 패딩: 96px (모든 슬라이드 동일).
- 그리드: 12칼럼, 거터 24px.
- 블록 간 간격 스케일: 8 / 16 / 24 / 40 / 64px 중에서만 선택한다. 임의의 다른 값을 쓰지 않는다.
- 기본 컬럼 배분은 비대칭이다: 8:4 또는 7:5 조합을 우선 사용하고, 6:6 좌우 대칭 배분은 쓰지 않는다.

## 5. Layout & Composition

원고의 슬라이드는 정보 구조가 서로 다른 9개 유형으로 나뉜다. 각 유형은 아래 레이아웃 규칙을 따른다.

| 유형 (대표 슬라이드) | 정보 구조 | 레이아웃 규칙 |
| --- | --- | --- |
| 표지형 (S01) | 제목 한 문장 + 부제 | 중앙 정렬 히어로를 쓰지 않는다. 제목을 좌측 또는 비대칭 위치에 크게 배치하고, 하단 정보는 캡션 크기로 최소화한다. |
| 장면·지표형 (S02) | 관찰 장면 + 시간 흐름 + 핵심 수치 2개 | 8:4 배분. 왼쪽 8칸에 가로 타임라인(회의 종료 → +50분 → +1시간), 오른쪽 4칸에 Metric-Primary·Metric-Secondary를 세로로 배치한다. |
| 진단 세부형 (S03) | 전체 항목 수 + 누락 항목 3종 | 전체 수치(31개)를 기준점으로 크게 두고, 누락 항목 3종은 그보다 작은 동일 크기의 보조 목록으로 나란히 배치해 "전체 대비 부분"이 읽히게 한다. |
| 절차 흐름형 (S04) | 순차 단계 4개 | 좌상단에서 우하단으로 내려가는 계단형 배치. 각 단계는 왼쪽 테두리 선으로 연결하고, 마지막 단계만 Accent로 강조해 도착점임을 표시한다. |
| 산출물 카드형 (S05) | 결정 카드 5필드(결정·다음 행동·담당/기한·이유·확인할 점) | Decision Card 컴포넌트를 7~8칸 폭에 배치한다. "결정"과 "다음 행동"은 Metric-Secondary 크기로 동일하게 크게, "이유·확인할 점"은 Body보다 작고 Muted 색으로 낮춘다. |
| 역할 대비형 (S06) | AI 역할 목록 vs 사람 역할 목록 | 좌우 비대칭(7:5 또는 5:7) 2단 배치. 두 목록을 같은 크기로 나열하되 구분선 하나로만 분리하고, 별도의 카드 박스나 배경색 차이를 주지 않는다. |
| 계획·비교형 (S07) | 4주 단계 + 사전 진단 대 목표 비교표 | 상단에 4단 가로 스트립(1~4주차), 하단에 "측정 항목 / 사전 진단 / 4주 파일럿 목표" 비교표를 배치한다. 스트립의 마지막 단계(4주차)만 Accent로 표시한다. |
| 요청·금지 대비형 (S08) | 요청 3가지 vs 하지 않는 것 3가지 | 좌우 비대칭 2단 배치(요청을 넓은 쪽에). "하지 않는 것"은 Muted 색과 작은 크기로 낮춰 부차적 정보임을 표시한다. |
| 마무리 선언형 (S09) | 핵심 문장 한 줄 + 하단 제안 | 화면 대부분을 핵심 문장에 할애하고, 하단 제안 문구는 Caption 크기로 최소화한다. 중앙 정렬 히어로를 쓰지 않고 좌측 또는 비대칭 정렬을 유지한다. |

## 6. Components

`design-preview.html`에서 사용한 컴포넌트 중 5개를 공통 컴포넌트로 채택한다.

1. **Decision Card**: 결정 · 다음 행동 · 담당·기한 · 이유 · 확인할 점 5개 필드를 가진 카드. Surface 배경, Line 테두리(그림자 없음). "결정"만 Accent 색을 적용할 수 있다. S05에서 사용한다.
2. **Timeline**: 상단에 1px Line 색 가로선을 긋고, 그 위에 시간 마커(점)와 캡션(시각) + 설명을 배치한다. S02에서 사용한다.
3. **Flow Step**: 번호(IBM Plex Mono, Muted) + 설명(Body)으로 구성된 계단형 목록. 왼쪽 테두리 선으로 단계를 연결한다. S04에서 사용한다.
4. **Data Label Chip**: IBM Plex Mono 16px 텍스트 위에 1px Line 색 실선을 얹은 라벨. 배경색이나 둥근 배지 형태를 쓰지 않는다. "교육용 가상 데이터" 표기에 사용한다(outline.md 발표 메타의 요구사항).
5. **Comparison Table**: 항목 / 사전 진단 / 목표 형태의 표. 구분선(Line 색)만으로 행을 나누고, 배경색 줄무늬나 강조 셀 배경을 쓰지 않는다. S07에서 사용한다.

## 7. Motion & Interaction

- 기본값은 모션 없음이다. 모션은 `prefers-reduced-motion: no-preference`가 확인될 때만 추가한다.
- 허용되는 모션은 슬라이드 진입 시 페이드 + 6px 이내의 짧은 이동(fade-up)뿐이며, 길이는 260ms, 이징은 ease-out으로 고정한다.
- 반복 애니메이션, 펄스, 바운스, 무한 루프, 시선을 끄는 강조 모션은 쓰지 않는다.
- `prefers-reduced-motion: reduce` 환경에서는 모든 트랜지션을 제거하고 최종 상태를 즉시 표시한다.

## 8. Voice & Brand

- 문장은 개조식으로, 단정하고 구체적으로 쓴다. "혁신적인", "놀라운", "완벽한", "게임 체인저" 같은 과장 부사·수식어는 쓰지 않는다.
- 원고의 수치를 슬라이드에 표시할 때는 outline.md의 발표 메타에 따라 항상 "교육용 가상 데이터"임을 라벨로 함께 표기한다.
- 이모지와 느낌표는 쓰지 않는다. 문장은 마침표로 끝낸다.
- 사람을 탓하는 어조를 피한다("~하지 않았다"보다 "~하는 방식이 통일되지 않았다"처럼 시스템·프로세스 문제로 서술한다).

## 9. Anti-patterns

- Inter, Roboto, Arial, Helvetica, system-ui, Space Grotesk 서체를 쓰지 않는다.
- 보라-파랑 그라데이션을 쓰지 않는다.
- glassmorphism, 반투명 블러 카드, box-shadow를 쓰지 않는다.
- 장식용 이모지 아이콘을 쓰지 않는다.
- 가운데 정렬 히어로와 3개 균등 카드 조합을 쓰지 않는다.
- 모든 슬라이드에 같은 레이아웃을 반복하지 않는다(5절의 슬라이드 유형별 레이아웃을 따른다).
- 의미 없는 아이콘과 과도한 장식을 쓰지 않는다.
- 슬라이드당 Accent 색을 2곳 이상 쓰지 않는다.
- outline.md와 design-preview.html에 없는 색상·폰트·수치·사례를 임의로 추가하지 않는다.
