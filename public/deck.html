Recap ① · Claude Code 전환

터미널에서 일하는 에이전트 —
사전 지식 네 가지

한 장 요약
1정의·루프터미널에서 자연어로 대화하는 CLI 에이전트 — 계획 → 파일 읽기 → 작성·실행 → 검증을 스스로 반복, 수정 전 승인 요청
2터미널pwd·ls·mkdir·cd 네 개면 폴더 사이 이동 충분 — 나머지 명령은 Claude에게 위임
3Git커밋으로 시점을 저장, 언제든 되돌리기 가능 — 명령 실행은 Claude가 대신, 사람은 "저장해줘·되돌려줘"면 충분
4CLAUDE.md·권한 모드폴더에 상주하는 지시서로 반복 설명 제거 · 권한은 Default → acceptEdits → plan 3단계로 조절

부담 제로 — Git 용어 여섯 개도 명령어도 외울 필요 없음 · 사람은 원하는 결과를 말로 지시, 실행은 전부 Claude 담당

AI 업무 자동화 SESSION 04 · 도구 선택
우열이 아니라 분업이라는 결론을 다시 짚는다 — 문서 업무는 Cowork, 커넥터 밖·코드 결합 작업만 Code로 넘어간다. 판별 질문 두 개는 "무조건 Code로 가는 게 아니라 커넥터로 되는지 먼저 본다"는 순서가 핵심 — 오늘 새 프로젝트를 고를 때도 이 두 질문을 먼저 던지게 한다.

Recap ④ · 커스텀 MCP · 한글(HWP)

커넥터 목록은 한계선이 아니다 —
MCP로 직접 연결

흐름 네 단계
1배경.hwp·.hwpx는 공식 커넥터가 없는 전용 포맷 — MCP 서버의 파싱 도구로 해결

Recap ⑤ · 발표자료 제작 배경

AI 티가 나는 이유 —
LLM은 평균값을 낸다

구체적 제약이 없으면 LLM은 학습 데이터의 통계적 평균값으로 수렴한다 — 보라~파랑 그라데이션 · Inter 폰트 · 3분할 카드 같은 "AI 슬롭"이 그 결과다. "AI 티 없애줘"라는 지시 자체도 다시 평균으로 수렴하는 게 역설.

층해결하는 문제수단
① 제약층평균 수렴(AI 티)CLAUDE.md · DESIGN.md · 안티 AI-슬롭 금지 목록 · 레퍼런스 이미지
② 생성층구조 없는 산출물단계별 워크플로(발견 → 구조 → 스타일 → 생성 → 검증)
③ 검증층에이전트가 결과를 못 봄스크린샷 검증 루프 · 좌표 지정 정밀 수정
