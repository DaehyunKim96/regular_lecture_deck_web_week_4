왜 다 똑같아 보일까 —
LLM은 평균값을 낸다

LLM은 학습 데이터의 통계적 평균값을 출력한다. 구체적 제약이 없으면 "가장 흔한 답"으로 수렴하고, 그 결과가 사람들이 AI 슬롭(AI slop)이라 부르는 미감이다 — AI가 못 만들어서가 아니라, 제약을 안 주면 평균으로 수렴하도록 설계돼 있어서 생기는 문제.

### 배경
우리는 여러 공급사가 입점한 이커머스 플랫폼을 운영하고 있어. 데이터는 이미 SQLite로 적재해뒀고, 경영진에게 보고할 대시보드가 필요해.
지금 답을 알아야 하는 질문은 3개야.

### 답해야 할 질문 3가지
**1. 어느 공급사가 매출과 수익 대부분을 차지하나?**
- 공급사별 매출(`net_amount` 합계)과 수익(`commission_amount` 합계)을 각각 집계해줘
- 상위 공급사가 전체에서 차지하는 **누적 비중**을 보여줘 (상위 1곳, 상위 3곳이 몇 %인지)
- 매출 1위와 수익 1위가 다를 수 있어. 수수료율(`commission_rate`)이 공급사마다 7%~20%로 다르거든.
  **매출은 크지만 수익 기여는 작은 공급사**가 있는지 반드시 짚어줘
- 한두 곳에 쏠려 있다면 그 자체가 리스크야. 쏠림 정도를 한 문장으로 판단해줘

**2. 고객은 결제 전 어느 단계에서 가장 많이 떠나나?**
- 퍼널: `product_view` → `add_to_cart` → `begin_checkout` → `purchase`
- **각 단계별 전환율과 이탈률**을 보여주고, 이탈이 가장 큰 구간을 강조해줘
- 주의: 이벤트 건수를 그냥 세면 안 돼. 한 세션에서 같은 이벤트가 여러 번 찍힐 수 있으니 **`session_id` 기준 distinct 카운트**로 계산해줘
- 가능하면 `device_type`, `traffic_source`, `is_member`별로 쪼개서 어느 집단의 이탈이 특히 심한지도 보여줘

**3. 할인 쿠폰을 준 고객이 실제로 더 사고, 다시 돌아오나?**
- `coupon_experiments` 테이블이 A/B 테스트 결과야. 그룹은 3개: `control`(쿠폰 없음), `treatment_amount`(정액 할인), `treatment_rate`(정률 할인)
- 그룹별로 **구매전환율**(`first_purchase`가 있는 비율), **재구매율**(`repurchase_7d`), **평균 구매금액**(`net_amount`), **쿠폰 사용률**(`used_coupon`)을 비교해줘
- 정액 할인과 정률 할인 중 **어느 쪽이 더 효과적인지** 판단해줘
- 중요: 전환율이 올라도 평균 구매금액이 깎이면 남는 게 없을 수 있어. **할인 비용을 감안해도 이득인지** 같이 따져줘

### 만드는 방법
**데이터 파이프라인**: React는 브라우저에서 도는 정적 앱이라 SQLite 파일을 직접 못 읽어. 그러니 이렇게 해줘.

1. Python 스크립트(`build_dashboard_data.py`)로 `ecommerce.db`에 SQL을 날려 집계
2. 결과를 `dashboard/src/data/*.json`으로 저장
3. React는 그 JSON을 import해서 렌더

집계는 **SQL에서** 끝내줘. 원본 7.5만 행을 그대로 JSON으로 뽑아서 브라우저에서 계산하지 마. 무겁고, 실습에서 SQL을 보여주는 게 목적이야.

**기술 스택**

- 차트는 Recharts
- 스타일은 CSS 파일로. Tailwind 같은 빌드 설정 추가는 하지 마
- 외부 API 호출 없이 완전히 로컬에서 동작해야 함

**화면 구성**
- 최상단에 핵심 지표 카드 4개 (총 매출, 총 수익, 주문 수, 전체 구매전환율)
